## Overview & Context

Autotune is implemented as a new `GavelWorkflow` subclass that orchestrates an iterative optimization loop over the existing `ScenarioProcessorStep` and `JudgeRunnerStep` without modifying them. A new composite step — `AutotuneIterationStep` — owns the loop and convergence logic. It creates a lightweight `IterationRunContext` per iteration that redirects DataSources to `iterations/iteration_N/` subdirectories while sharing the outer evaluation context.

A `TuningAgent` class wraps the existing `ProviderFactory` to call an LLM meta-optimizer. It receives judge feedback from the iteration's `output_judged.jsonl`, builds a meta-prompt from a user-overridable TOML template, calls the configured model, and returns an improved prompt text. `TuneStep` persists this as a new version in `runs/<id>/prompts.toml` using the `toml` library (already a project dependency).

The agent skill extension adds an autotune section to the existing `gavel-skill/SKILL.md` and updates the two relevant reference files.

### Cross-Cutting Concerns

1. **No mutation of existing steps** — `ScenarioProcessorStep` and `JudgeRunnerStep` must work for autotune by receiving a different context, not by adding autotune-specific branches inside them.
2. **Error policy propagation** — `AutotuneWorkflow` reads `eval_config.error_policy` and passes it to every `step.safe_execute()` call, including inner iteration steps.
3. **OTel spans** — Every TuningAgent LLM call must emit an OpenTelemetry span via the project's `get_tracer()`. Iteration number must be recorded as a span attribute.
4. **TOML consistency** — Use `toml.dumps()` for writing and `tomllib.loads()` for reading prompt version files. Both are already available (`toml>=0.10.0` in deps; `tomllib` is stdlib Python 3.11+).
5. **Existing CLI conventions** — `autotune` commands use `Annotated[Optional[str], typer.Option(...)] = None` for `--eval-root` and `--run`, exactly matching the `oneshot` pattern.

### Brownfield Notes

- `EvalConfig.workflow_type` is currently `Literal["oneshot", "conversational"]` — must be extended to include `"autotune"`. This is additive and backward-compatible.
- `StepPhase` enum needs two new values: `AUTOTUNE_ITERATION` and `TUNING`.
- `LocalRunContext` is initialized with a `base_dir` pointing to the run directory. For autotune we need per-iteration contexts; we will add a `skip_snapshot: bool = False` parameter to suppress config snapshotting on per-iteration context creation.
- The existing `toml` library (`toml.dumps()`) can write TOML. No new dependency needed.
- The `gavel-skill/references/cli-reference.md` is auto-generated by `scripts/update_cli_reference.py` — running it after CLI implementation is sufficient; no manual edits needed.

## Architecture Decisions (ADRs)

### ADR-AT-1: Introduce `CompositeStep` base class; `AutotuneIterationStep` subclasses it

**Decision:** Add `CompositeStep(Step)` to `core/steps/base.py`. `AutotuneIterationStep` subclasses it and calls `run_children()` once per iteration with an `IterationRunContext`.

**Rationale:** `AutotuneIterationStep` contains three inner steps (`ScenarioProcessorStep`, `JudgeRunnerStep`, `TuneStep`) that are the same kind of first-class workflow steps as the outer pipeline uses. Without `CompositeStep`, those inner steps are called as raw objects — bypassing `safe_execute()`, `.workflow_status` tracking, and OTel spans. A `CompositeStep` base fixes this: it owns a `child_steps` list and a `run_children()` method that calls each child through `safe_execute()` with the inherited error policy. The result is uniform error handling, per-step crash recovery records, and consistent observability — without duplicating any of that logic inside the loop body.

**Affects:** `core/steps/base.py` (new `CompositeStep`), `core/steps/autotune_iteration_step.py`

```python
class CompositeStep(Step):
    """Base class for steps that loop over an ordered list of child steps."""

    def __init__(self, child_steps: list[Step], logger: logging.Logger):
        super().__init__(logger)
        self.child_steps = child_steps

    async def run_children(
        self,
        context: RunContext,
        error_policy: ErrorPolicy,
    ) -> bool:
        """Run each child step via safe_execute(); return False on first failure."""
        for step in self.child_steps:
            ok = await step.safe_execute(context, error_policy)
            if not ok:
                return False
        return True
```

`AutotuneIterationStep` calls `run_children(iteration_ctx, error_policy)` per iteration, skipping `TuneStep` (the last child) when convergence is detected before it would run.

### ADR-AT-2: Per-iteration context via `IterationRunContext` — share `eval_ctx`, redirect DataSources

**Decision:** Create `IterationRunContext` — a thin dataclass that wraps the outer `LocalRunContext` and provides `results_raw`, `evaluation_results`, and `run_dir` pointed at `iterations/iteration_N/`. `eval_ctx`, `run_logger`, and `run_id` are shared from the outer context.

**Rationale:** `ScenarioProcessorStep` and `JudgeRunnerStep` interact with RunContext through DataSources (`context.results_raw`, `context.evaluation_results`, `context.run_dir`). By replacing these three attributes, the existing steps route their I/O to the iteration subdirectory without modification. The alternative — creating a full `LocalRunContext` per iteration — would trigger config snapshotting, logger initialization, and telemetry setup per iteration, which is wasteful and produces redundant artifacts.

**Affects:** `core/contexts.py`, `core/steps/autotune_iteration_step.py`, `core/steps/scenario_processor.py` (read-only, must not change), `core/steps/judge_runner.py` (read-only, must not change)

```python
@dataclass
class IterationRunContext:
    """Thin per-iteration context that redirects DataSources to iterations/iteration_N/."""
    eval_ctx: EvalContext           # shared from outer run
    run_id: str                     # shared from outer run
    run_logger: logging.Logger      # shared from outer run
    run_dir: Path                   # iterations/iteration_N/
    results_raw: RecordDataSource   # → run_dir/output_raw.jsonl
    evaluation_results: RecordDataSource  # → run_dir/output_judged.jsonl
    last_step_error: Optional[Exception] = None
    processor_results: List[OutputRecord] = field(default_factory=list)
    evaluation_results_data: List[JudgedRecord] = field(default_factory=list)
    deterministic_metrics: Dict[str, Any] = field(default_factory=dict)

    def mark_step_complete(self, phase: StepPhase) -> None:
        pass  # no-op; outer context tracks top-level steps only
```

### ADR-AT-3: `TuningAgent` uses `ProviderFactory` directly

**Decision:** `TuningAgent` instantiates an LLM agent via `ProviderFactory.create_agent(model_id, agents_config)` — the same factory used by `PromptInputProcessor`. It makes a single async call per iteration.

**Rationale:** Avoids introducing a second LLM abstraction. `ProviderFactory` already handles provider auth, model config, and pydantic-ai agent creation for all supported providers. TuningAgent is just another consumer of this factory.

**Affects:** `core/autotune/tuning_agent.py`, `providers/factory.py` (no changes needed)

---

### ADR-AT-4: Prompt versions stored in `runs/<id>/prompts.toml`, not in the eval's `config/prompts/`

**Decision:** The run-local `prompts.toml` in the outer run directory holds all generated versions (v1 copied at PrepareStep, v2+ appended by TuneStep). The eval's `config/prompts/<name>.toml` is the source of truth for v1 only and is never modified.

**Rationale:** Keeps the eval directory read-only during runs (immutability invariant). Multiple concurrent autotune runs can run against the same eval without racing. The run's `.config/` snapshot already captures v1 for reproducibility. Generated versions belong to the run artifact, not the eval definition.

**Affects:** `core/steps/tune_step.py`, `core/workflows/autotune.py` (PrepareStep logic), `cli/scaffolding.py`

---

### ADR-AT-5: Convergence check fires before `TuneStep` on the final iteration

**Decision:** After `JudgeRunnerStep` completes for iteration N, evaluate all four convergence criteria. If any fires, record convergence and skip `TuneStep` (no wasted LLM call for a prompt that won't be used). The loop exits and `ReportingStep` runs.

**Rationale:** Avoids paying for a TuningAgent call on the iteration that triggers early stopping. The converged report still shows the full score history for all completed iterations.

**Affects:** `core/steps/autotune_iteration_step.py`

```python
converged, reason = self._check_convergence(iteration, current_score, previous_score, config)
if converged:
    break
await tune_step.safe_execute(iteration_ctx, error_policy)
```

---

### ADR-AT-6: `AutotuneReporter` extends `Jinja2Reporter` with a new template

**Decision:** Create `AutotuneReporter(Jinja2Reporter)` that builds an autotune-specific `ReportData`-like context dict and renders `templates/autotune.html`. The HTML template uses vanilla JS for the score progression table (no external chart library).

**Rationale:** `Jinja2Reporter` already handles file writing and template loading. A subclass that overrides `_build_context()` is all that's needed, matching the `OneShotReporter` pattern. No chart library dependency is introduced — a simple HTML table with inline CSS highlights the best row.

**Affects:** `reporters/autotune_reporter.py`, `reporters/templates/autotune.html`

## API & Interface Design

### CLI Commands

```
gavel autotune create <eval-name> [--eval-root DIR]
  Creates eval directory with autotune scaffold:
  - config/eval_config.json (workflow_type: "autotune", tuning section with defaults)
  - config/agents.json (empty template)
  - config/prompts/<eval-name>.toml (v1 placeholder)

  Prints next-step instructions.

gavel autotune run --eval <name> [--eval-root DIR] [--run <run-id>]
  Executes or resumes AutotuneWorkflow.
  --run: resume an interrupted run from its existing iteration state.
  Prints run_id and final report path on success.
  Prints Rich error panel to stderr on failure.
```

### Key Interfaces

**`AutotuneWorkflow`**:
```python
class AutotuneWorkflow:
    def __init__(self, eval_ctx: LocalFileSystemEvalContext, logger: logging.Logger): ...
    async def execute(self, resume_run_id: Optional[str] = None) -> LocalRunContext: ...
```

**`AutotuneIterationStep(CompositeStep)`** — the loop:
```python
class AutotuneIterationStep(CompositeStep):
    def __init__(self, logger: logging.Logger):
        super().__init__(
            child_steps=[ScenarioProcessorStep(logger), JudgeRunnerStep(logger), TuneStep(logger)],
            logger=logger,
        )

async def execute(self, context: LocalRunContext) -> None:
    """
    Reads TuningConfig from eval_ctx. For each iteration:
      1. Creates IterationRunContext for iterations/iteration_N/
      2. Calls run_children(iteration_ctx, error_policy) — runs
         ScenarioProcessorStep → JudgeRunnerStep via safe_execute()
      3. Checks convergence — if met, writes IterationMetadata and breaks
         (TuneStep child is skipped on the final iteration)
      4. Calls safe_execute() on TuneStep with iteration_ctx
      5. Writes IterationMetadata to metadata.json
    Writes AutotuneRunSummary to run_summary.json on exit.
    """
```

**`TuningAgent`**:
```python
class TuningAgent:
    def __init__(self, model_id: str, agents_config: dict, temperature: float = 0.7): ...

    async def generate_improved_prompt(
        self,
        current_prompt: str,
        judge_feedback: list[dict],
        iteration: int,
        eval_dir: Path,
    ) -> tuple[str, dict]:
        """
        Returns (improved_prompt_text, analysis_metadata).
        Loads meta-prompt from eval_dir/config/prompts/autotune.toml if present,
        falls back to bundled processors/autotune_template/autotune.toml.
        """
```

**`TuneStep`**:
```python
class TuneStep(Step):
    @property
    def phase(self) -> StepPhase: return StepPhase.TUNING

    async def execute(self, context: IterationRunContext) -> None:
        """
        Loads current prompt vN from outer run's prompts.toml.
        Aggregates judge feedback from context.run_dir/output_judged.jsonl.
        Calls TuningAgent.generate_improved_prompt().
        Appends vN+1 to outer run's prompts.toml.
        """
```

No existing CLI commands are changed. The `oneshot` and `conv` command groups are untouched. `EvalConfig` additions are optional fields — existing `eval_config.json` files without a `tuning` section continue to parse without error.

## Implementation Patterns & Conventions

### Naming Conventions

Follow existing project conventions (snake_case functions/fields, PascalCase classes). New constructs:

| Construct | Name |
|-----------|------|
| Workflow | `AutotuneWorkflow` |
| Iteration step | `AutotuneIterationStep` |
| Tune step | `TuneStep` |
| Per-iteration context | `IterationRunContext` |
| Meta-optimizer | `TuningAgent` |
| Reporter | `AutotuneReporter` |
| Config model | `TuningConfig` |

### Error Handling

Follow the existing pattern — use `error_policy.should_halt(tier)` for all exceptions within the iteration loop. Specifically:

- **TuningAgent failure**: classify as `ERROR`; `safe_execute()` on `TuneStep` will raise `RunPolicyError` if `exit_on_error=True`. The iteration fails but already-completed iterations are preserved.
- **Per-scenario failure inside `ScenarioProcessorStep`**: handled by existing step logic (logged, written as error record, does not abort iteration).
- **Convergence check failure** (e.g., bad score calculation): classify as `ERROR`, abort loop.

Never catch `RunPolicyError` inside `AutotuneIterationStep` — let it propagate to `AutotuneWorkflow.execute()`.

### Prompt Variable Preservation

Before appending vN+1 to `prompts.toml`, validate that all `$var` placeholders from v1 are present in the generated text:

```python
import re
original_vars = set(re.findall(r'\$\{?([a-zA-Z_][a-zA-Z0-9_]*)\}?', v1_prompt))
generated_vars = set(re.findall(r'\$\{?([a-zA-Z_][a-zA-Z0-9_]*)\}?', generated_prompt))
missing = original_vars - generated_vars
if missing:
    logger.warning(f"TuningAgent dropped variables {missing}; retrying once")
    # retry once; if still missing, log error and abort iteration
```

### Testing Pattern

Unit tests mock `ProviderFactory` and the file system:

## Security & Performance

### Security

| Concern | Mitigation |
|---------|-----------|
| Meta-prompt template file as attack vector | File is read as data (TOML string); no `eval()` or `exec()`. Pydantic validates structure. Path is resolved relative to `eval_dir` with traversal check (matching existing `markdown_path` pattern). |
| TuningAgent-generated prompt injection | Generated prompt is stored as a versioned string; it is only passed to the LLM as a prompt template, not executed. Placeholder validation (`$var`) uses `re.findall`, not `eval`. |
| Provider credentials | Handled exclusively by existing `ProviderFactory` — no new credential handling in TuningAgent. |
| Autotune scaffold overwrites existing files | `autotune create` checks for existing eval dir and refuses to overwrite without `--force` (matching `oneshot create` behavior). |

### Performance

| Concern | Target | Approach |
|---------|--------|---------|
| Per-iteration processing time | Same as equivalent OneShot run | `IterationRunContext` reuses outer `eval_ctx`; no re-loading of config/scenarios |
| TuningAgent call latency | ≤ 10 s | Single LLM call per iteration; async; no parallelism needed (one prompt to generate) |
| Total 5-iteration run (10 scenarios) | < 5 minutes | Inherits existing `AsyncWorkerPool` parallelism for scenario execution |
| Report generation | < 1 s | Jinja2 template render over O(N iterations) data |

### Observability

- **Logs:** Each iteration logs `INFO: Starting iteration N/max_rounds` and `INFO: Iteration N complete, score=X.X`. Convergence logs at `INFO` with reason. TuneStep logs prompt version generated.
- **OTel Spans:**
  - `autotune.iteration` span wrapping each full iteration (attributes: `iteration`, `score`, `converged`)
  - `autotune.tune` span wrapping the TuningAgent LLM call (attributes: `iteration`, `model_id`, `prompt_version`)
- **Metrics:** `AutotuneRunSummary` written to `run_summary.json` on loop exit — this is the machine-readable convergence record.

## Implementation Sequence
